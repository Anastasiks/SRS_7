# StudyFlow — архитектура приложения

## 1. Общая архитектура

StudyFlow — веб-приложение для управления проектами и задачами. Приложение разработано на Django и использует Django REST Framework для предоставления REST API.

Архитектура включает следующие компоненты:

- **Frontend** — HTML-шаблоны Django, отображающие страницы и интерфейс управления задачами.
- **Django Views** — обработка HTTP-запросов от пользователя, формирование страниц и обработка AJAX-запросов.
- **REST API** — предоставление данных и выполнение операций с задачами, проектами и историей изменений.
- **Django ORM** — взаимодействие с базой данных через модели приложения.
- **База данных** — SQLite при локальной разработке и PostgreSQL при соответствующем подключении на Render.

## 2. Схема архитектуры

```text
┌──────────────────────────────┐
│           Пользователь       │
│      Браузер и HTML-интерфейс│
└──────────────┬───────────────┘
               │ HTTP / AJAX
               ▼
┌──────────────────────────────┐
│         Django Views         │
│   Страницы и AJAX-операции   │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│       Django REST Framework  │
│  ViewSets, сериализаторы,    │
│  права доступа, переходы     │
│  статусов задач              │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│          Django ORM          │
│    Project, Task, Activity   │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│         База данных          │
│       SQLite / PostgreSQL    │
└──────────────────────────────┘
```

Схема показывает основные уровни приложения. HTML-интерфейс взаимодействует с Django Views, а REST API обрабатывает запросы к ресурсам через представления и сериализаторы. Доступ к данным осуществляется посредством Django ORM.

## 3. Основные компоненты проекта

### 3.1. `config`

Содержит основные настройки Django-проекта:

- `settings.py` — конфигурация приложений, базы данных, безопасности и статических файлов;
- `urls.py` — корневые маршруты приложения;
- `wsgi.py` — точка входа для WSGI-сервера.

### 3.2. `dashboard`

Основное приложение StudyFlow, отвечающее за управление проектами и задачами.

Основные компоненты:

- `models.py` — модели проекта, задачи и истории действий;
- `views.py` — представления страниц, AJAX-операции и REST API;
- `serializers.py` — преобразование моделей в JSON и проверка входных данных;
- `urls.py` — маршруты интерфейса и REST API;
- `templates/` — HTML-шаблоны пользовательского интерфейса.

### 3.3. REST API

Для работы с данными используются следующие ресурсы:

- `/api/tasks/` — просмотр, создание, изменение и удаление задач, а также переходы между статусами;
- `/api/projects/` — чтение списка проектов и информации об отдельных проектах;
- `/api/history/` — просмотр истории действий;
- `/api-auth/` — маршруты авторизации Django REST Framework.

Для основных REST API ViewSet используются сериализаторы и проверка прав доступа. Операции с задачами ограничиваются задачами текущего пользователя согласно реализации `TaskViewSet`.

### 3.4. Модели данных

Приложение использует три основные модели:

- `Project` — название, описание и дата создания проекта;
- `Task` — название, описание, проект, владелец, исполнитель, статус, приоритет, срок и причина отклонения;
- `Activity` — тип события, описание, связанная задача, пользователь-инициатор и время события.

Связи между моделями и правила целостности данных подробно описаны в `DATABASE.md`.

## 4. Обработка запросов

При работе с HTML-интерфейсом браузер отправляет HTTP-запрос Django. Представление обрабатывает запрос, обращается к моделям через ORM и возвращает HTML-страницу.

При использовании REST API запрос обрабатывается соответствующим ViewSet. Сериализатор преобразует данные в JSON и проверяет входные значения. Для изменения статуса задачи применяется отдельный endpoint перехода, проверяющий допустимость перехода и необходимые права пользователя.

Для некоторых операций интерфейса используются AJAX-запросы, которые возвращают JSON с результатом выполнения или сообщением об ошибке.

## 5. Работа с базой данных

Локально приложение использует SQLite. При развёртывании на Render может использоваться PostgreSQL, если задана переменная окружения `DATABASE_URL`.

Модели Django определяют структуру данных, а миграции позволяют создавать и обновлять таблицы. Изменение статуса задачи через REST API выполняется вместе с созданием записи истории в рамках транзакции.

Локальная база данных и база данных Render являются отдельными хранилищами. Данные между ними автоматически не синхронизируются.

## 6. Безопасность

В проекте предусмотрены следующие механизмы:

- хранение настроек через переменные окружения;
- проверка допустимых переходов статусов задач;
- аутентификация и проверка прав доступа для основных REST API ViewSet;
- CSRF-защита запросов, для которых она предусмотрена Django;
- использование HTTPS и защищённых cookie при отключённом режиме отладки согласно настройкам проекта.

## 7. Развёртывание

В облачной среде Render приложение запускается через WSGI с использованием Gunicorn. Для обслуживания статических файлов применяется WhiteNoise.

Параметры запуска и переменные окружения описаны в `deployment.md`.
