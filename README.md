# StudyFlow

StudyFlow — веб-приложение для управления проектами и задачами. Проект разработан на Django и предоставляет HTML-интерфейс и REST API для работы с данными.

## Возможности

- Просмотр сводной информации на главной странице.
- Просмотр проектов и задач.
- Создание задач через AJAX-запрос.
- Изменение статуса и удаление задач.
- Работа с задачами через REST API.
- Управление жизненным циклом задачи с проверкой допустимых переходов.
- Просмотр истории изменений.
- Разграничение доступа к REST API по пользователям.

## Технологический стек

- Python 3.12
- Django
- Django REST Framework
- SQLite для локальной разработки
- PostgreSQL для развёрнутого окружения
- HTML-шаблоны Django
- Git и GitHub
- Render для размещения приложения

Версии библиотек и Python следует сверять с `requirements.txt` и фактическим окружением.

## Локальный запуск

### 1. Получение исходного кода

```powershell
git clone https://github.com/Anastasiks/SRS_7.git
cd SRS_7
```

Если проект уже открыт в PyCharm, повторно клонировать репозиторий не нужно.

### 2. Создание виртуального окружения

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Настройка окружения

В проекте предусмотрен файл `.env.example` с примерами переменных окружения. Он не содержит настоящих секретов.

Перед запуском проверь настройки в `config/settings.py`. Если приложение не загружает `.env` автоматически, переменные нужно задать в окружении терминала или в конфигурации запуска PyCharm.

Для локальной разработки используются настройки `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` и `DATABASE_URL`. При отсутствии `DATABASE_URL` проект использует SQLite.

### 5. Проверка конфигурации и миграций

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate
```

### 6. Создание администратора

При необходимости создать пользователя для административной панели:

```powershell
python manage.py createsuperuser
```

### 7. Запуск сервера разработки

```powershell
python manage.py runserver
```

После запуска приложение доступно по адресам:

- Главная страница: http://127.0.0.1:8000/
- Проекты: http://127.0.0.1:8000/projects/
- Задачи: http://127.0.0.1:8000/tasks/
- REST API: http://127.0.0.1:8000/api/
- Административная панель: http://127.0.0.1:8000/admin/

Сервер разработки предназначен для локальной работы, а не для промышленной эксплуатации.

## REST API

Основные маршруты API:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/tasks/` | Получение списка задач |
| POST | `/api/tasks/` | Создание задачи |
| GET | `/api/tasks/{id}/` | Получение задачи |
| PUT, PATCH | `/api/tasks/{id}/` | Изменение задачи |
| DELETE | `/api/tasks/{id}/` | Удаление задачи |
| POST | `/api/tasks/{id}/transition/` | Изменение статуса с проверкой перехода |
| GET | `/api/projects/` | Получение списка проектов |
| GET | `/api/projects/{id}/` | Получение проекта |
| GET | `/api/history/` | Получение истории изменений |

Для REST API требуется авторизация пользователя. Список задач и история изменений ограничиваются данными, доступными текущему пользователю согласно логике приложения.

Дополнительные AJAX-маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/tasks/create/` | Создание задачи через интерфейс |
| POST | `/api/tasks/{id}/status/` | Изменение статуса задачи |
| POST | `/api/tasks/{id}/delete/` | Удаление задачи через интерфейс |

AJAX-маршруты принимают POST-запросы. Для запросов, изменяющих данные, следует учитывать защиту Django от CSRF.

Подробные сведения о маршрутах, форматах запросов и ответов приведены в [API.md](API.md).

## База данных

В локальной конфигурации используется SQLite. По умолчанию файл базы данных — `db.sqlite3` в корне проекта.

В развёрнутом окружении может использоваться PostgreSQL, подключённая через переменную `DATABASE_URL`.

Основные модели приложения:

- `Project` — проект.
- `Task` — задача, связанная с проектом и пользователями.
- `Activity` — запись об изменении или событии, связанном с задачей.

Подробное описание моделей и связей приведено в [DATABASE.md](DATABASE.md).

## Проверка проекта

Для проверки конфигурации Django:

```powershell
python manage.py check
```

Для проверки отсутствия новых изменений моделей:

```powershell
python manage.py makemigrations --check --dry-run
```

Для применения миграций:

```powershell
python manage.py migrate
```

Для запуска автоматических тестов:

```powershell
python manage.py test
```

В ходе проверки локального окружения подтверждены следующие результаты:

- `makemigrations --check --dry-run` завершилась сообщением `No changes detected`.
- `migrate` завершилась сообщением `No migrations to apply`.
- Главная страница локального приложения открывается.
- REST API проектов и задач доступен.
- Создание задачи и сохранение данных в локальной базе проверены.

Для развёрнутого окружения проверены доступность главной страницы и REST API проектов и задач. Создание задачи на Render также проверено вручную.

Результаты проверок следует подтверждать скриншотами, приложенными к отчёту.

## Безопасность

- Секретный ключ Django хранится в переменной окружения `DJANGO_SECRET_KEY`.
- Для развёрнутого окружения следует отключать режим отладки через `DJANGO_DEBUG=False`.
- `DJANGO_ALLOWED_HOSTS` должен содержать разрешённые домены.
- `DJANGO_CSRF_TRUSTED_ORIGINS` должен быть настроен для используемых доверенных источников.
- Реальные секреты и пароли не следует добавлять в репозиторий.
- В рабочем окружении необходимо использовать настройки безопасности Django и конфигурацию HTTPS, соответствующие условиям развёртывания.
